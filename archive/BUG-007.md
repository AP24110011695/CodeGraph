# BUG-007 — Semantic Search Fails for Newly Indexed Repositories

## Summary

Semantic search (POST /repositories/{repository_id}/search) returned HTTP 500 for newly uploaded and indexed repositories, while it worked for the benchmark repository.

## Root Cause

The `_score_keyword_match` function in `app/search/search_service.py` line 208 was calling `.lower()` directly on symbol values, but these values are Pydantic `Symbol` objects instead of strings.

```python
# Before (BUG):
lowered_value = value.lower()  # AttributeError: 'Symbol' object has no attribute 'lower'

# After (FIX):
lowered_value = str(value).lower()  # Convert to string first
```

## Trace

1. Upload repository → Success
2. Index repository → Success
3. Build Repository Memory → Success
4. POST /repositories/{id}/search → HTTP 500

## First Failing Function

- **File:** `backend/app/search/search_service.py`
- **Function:** `_score_keyword_match`
- **Line:** 208
- **Error:** `AttributeError: 'Symbol' object has no attribute 'lower'`

## Fix

Changed line 208 in `backend/app/search/search_service.py`:

```python
# OLD (BUG):
lowered_value = value.lower()

# NEW (FIX):
lowered_value = str(value).lower()
```

## Verification

- Uploaded NEW repository (1cb60702-f656-46fb-aa7c-fc37b2b776a1)
- Indexed successfully
- Built Repository Memory successfully
- POST /repositories/{id}/search → HTTP 200 (6 results returned)

## Status

**RESOLVED** — Fix verified with NEW repository.

## Impact

- Affects all newly indexed repositories when using keyword or hybrid search modes
- Does not affect pure semantic search mode
- Benchmark repository appeared to work because it may have been using pure semantic search or the indexing pipeline at the time was different
